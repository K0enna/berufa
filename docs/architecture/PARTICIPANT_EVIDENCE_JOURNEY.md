## User outcome

The installed participant package now exposes one normal-user path instead of only a runtime smoke
command. A fully fictional user can:

1. read and accept the local synthetic-data boundary;
2. import one bundled UTF-8 plain-text career note;
3. review six atomic evidence proposals, all unapproved by default;
4. approve, edit, reject, defer, mark private, approximate, or unknown;
5. see whether the evidence slice is ready and why it is blocked;
6. select the customer/post-sales leadership pack or the confidence-capped generic fallback while
   recording practical constraints separately;
7. evaluate one exact deterministic posting with official-source semantics;
8. inspect mandatory, preferred, and optional requirements with `proven`, `disproven`, `conflict`,
   `unknown`, and `not_found` semantics;
9. record a pursue, conditional, hold, or skip decision without creating an application event;
10. generate a requirement map, decision HTML, application content brief, and interview briefing
    from approved application-safe evidence only;
11. explicitly confirm one synthetic local lifecycle event that cannot mean submitted;
12. export the documented user-owned records and local content-free metrics; and
13. preview and delete the entire synthetic instance while retaining the installed package.

The loopback surface binds only to `127.0.0.1`, validates the exact `Host`, refuses cross-site
writes, uses a per-process CSRF token, sets restrictive browser headers, serves no arbitrary files,
and logs no request content. Construction creates no participant data. The first filesystem effect
is the user's explicit consent receipt. Generated files are served only through four fixed
manifest-bound download names; the application never exposes a general file route.

## Evidence authority

`EvidenceVault` stores one instance-bound SQLite database under `data/evidence-vault.db`. Synthetic
text and parser-approved TXT, Markdown, PDF, or DOCX sources are stored as managed local copies.
Original bytes/hash, extracted text/hash, and exact line/page/part locations remain distinct;
content-free exports enumerate the source without copying either content field. Evidence content is
immutable per revision. Dispositions are append-only audit events, and only `local_user` may approve,
reject, defer, or revoke. Approval binds to the exact revision hash. Editing creates a new
unapproved revision; approving it supersedes the older approved revision.

The first strict evidence kinds cover role/timeline, responsibility and decision rights,
achievement and metric, education completion, genuine gap, and forbidden claim. The validators
prevent a synthetic team outcome from becoming sole personal ownership, a source that says no
degree from supporting an awarded degree, or gaps/forbidden claims from becoming publishable.
Source tampering blocks approval and readiness.

## Decision and external-authority boundary

`ParticipantFlow` is now an adapter over the shared versioned role-pack engine. Candidate overlay,
packaged structural meaning, exact posting fixture, recommendation, user decision, generated
artifacts, and confirmed lifecycle event remain separate inspectable records. The primary pack
distinguishes current people leadership, post-sales operations, direct new-logo AE leadership,
management layer, and budget ownership. The generic fallback caps confidence and cannot authorize
application readiness. `not_found` never becomes `disproven`, and transferable evidence never
silently becomes direct proof. The dossier shows pack version, content fingerprint, selection
status, adjacent route, and rescore-bound evaluation fingerprint.

Every material requirement row links to a posting requirement plus approved candidate evidence or
an explicit unknown. Private gaps inform the local decision but cannot become application claims.
The generated Markdown includes an exact evidence ID and revision for every affirmative claim.
Creating the package records no submission. The only lifecycle event in the synthetic path is
`synthetic_application_bundle_reviewed`, requires an explicit checkbox, and records
`external_event: false` and `application_submitted: false`.

## Export, metrics, and deletion

The complete local export enumerates source inventory, evidence revisions and audit, role
selection, posting evaluation, user decision, artifact hashes, confirmed synthetic lifecycle, and
local metrics. Metrics contain counts, timestamps, recommendation/decision categories, unresolved
question count, operator minutes, model-disabled state, and safety-failure counts. They contain no
raw candidate/posting text, employer or role URL, compensation, credentials, or remote telemetry.

Reset requires the exact phrase `DELETE SYNTHETIC INSTANCE`, verifies the recognized flow-state
marker, rejects broad filesystem roots or unexpected top-level state, inventories every file, and
removes only the selected participant instance. The post-delete screen reports the removed count
and explains that the installed package remains outside the instance.

## Synthetic, clean-room, and human proof

Mara Voss, Northstar Atlas Software, every timeline entry, and every metric are fictional. The
fixture contains no copied candidate data or external repository content. `rolevane-evidence-smoke`
proves the evidence tranche. `rolevane-journey-smoke` completes two isolated model-disabled full
demo journeys, generates four artifacts per demo, retains each completed synthetic export, and
resets each demo. Separately, it initializes two real workspace layouts, imports one synthetic
local source into each, exports that populated supported vault, and deletes only those selected
workspaces. The smoke fails on demo/workspace crossover, empty populated exports, external action,
model use, stale artifact hashes, or incomplete deletion.

Human observation script after installing the wheel:

1. Run `rolevane-product`; the browser opens to onboarding without repository configuration.
2. Confirm the local boundary and import the visibly fictional note.
3. Exercise approve, edit, defer then resolve, and reject on separate cards; verify the inbox stays
   below ten items and every edit returns to unapproved.
4. Choose customer/post-sales leadership and record the displayed practical constraints.
5. Evaluate the exact synthetic posting; verify official identity/hash, requirement levels,
   evidence routes, genuine gap, and explicit unknown are visible.
6. Record `conditional`; verify no application or lifecycle event appears yet.
7. Generate and download all four local artifacts. Confirm affirmative claims carry evidence
   references and the files say they are not submitted.
8. Confirm only the synthetic local-review event, create the full export, and inspect its manifest.
9. Preview reset, enter the exact phrase, delete, and verify the instance directory is gone.

Optional live-source guided smoke remains source-checkout-only and must use a public, supported ATS
URL chosen by the operator: `career-os evaluate URL --output tmp/live-ats-smoke.json`. It is
read-only, opt-in, uses the reviewed public-source transport, changes no pipeline/lifecycle state,
and is not required for the deterministic installed journey.

## Known limitations and deferred owners

- #35: the participant package now contains the bounded local-only parser foundation for UTF-8
  text/Markdown, classic-cross-reference text-searchable PDF, and ordinary single-disk DOCX. DOCX
  intake resolves one authoritative main part and its internal headers, footers, footnotes, and
  endnotes with exact part/paragraph provenance. Active content, external relationships, dangerous
  fields, excessive XML depth, compressed or hybrid PDF cross-reference streams, unsupported PDF
  filter chains, and ZIP64 or multidisk DOCX packages fail closed with bounded or compatibility
  errors. `rolevane-evidence-import` now persists a consent-bound managed source with both hashes
  and parser locations, but intentionally creates zero proposals. `rolevane-evidence-propose`
  accepts a strict private, source-bound JSON envelope and creates only an unapproved proposal with
  explicit origin and reason audit. `rolevane-evidence-interview` adds a resumable set of ten
  model-disabled questions whose strict private answers are retained as exact managed sources and
  mapped deterministically to unapproved proposals. Deterministic document extraction, adaptive
  questioning, the browser file picker, OCR, and full workspace ownership remain open.
  The generic issue #33 evidence contract is implemented in
  `docs/architecture/EVIDENCE_VAULT_CONTRACT.md`.
- #34: the shared schema/validator/registry/evaluator and reviewed Gate D founding-cohort packs now
  cover customer/post-sales, commercial, product, services/solutions, and senior-expert mandates.
  The participant walking skeleton remains bound to its exact customer fixture and fallback; the
  broader registry is exercised through synthetic pack fixtures, the explanation CLI, and dogfood
  trace adapters without changing application authority.
- #36: the installed product deliberately has no live provider. A strict private
  `rolevane-role-evaluate-supplied` route now persists and evaluates a visibly lower-authority
  user-supplied posting without fetching its URL or authorizing application readiness. Official URL
  intake remains open. The separate `rolevane-role-decide-supplied` route records only an exact,
  current, local-user-confirmed decision without creating an application or external event.
  Preparation, interviews, offers, outcomes, and the read-only focus projection remain open.
- #37: the reproducible wheel is the clean product artifact, not a signed Windows installer or
  updater; upgrade, rollback, backup/restore, and uninstall remain open.
- #38: this path is loopback, synthetic, bounded, model-disabled, and resettable, but it does not
  close the full product threat model, encryption, support-access, or incident-response work.
- #39: metrics are local/content-free and exportable, but there is no remote beta analytics or
  research-sharing flow.
- #40: no public launch, payment, beta terms, licence decision, or commercial claim is authorized.

The dogfood dashboard and CLI remain unchanged. Completing #70 proves integration only; it does not
