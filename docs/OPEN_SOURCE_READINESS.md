## Release artifact boundary

The supported distribution boundary is the exact `files` and `resources` allowlist in
`config/product_package.toml`, together with public `pyproject.toml`, `README.md`, `LICENSE`,
`NOTICE`, the package manifest, and the dependency-free build and release tools under `tools/`. The PEP 517 sdist
contains only those inputs and has one canonical root with fixed timestamps and modes; it can build
the same wheel after unpacking without the private checkout or Git metadata. Private modules,
private metadata, provider activation, and candidate data are not release inputs.

`RELEASE-MANIFEST.json` is deliberately a dependency inventory and build manifest, not a formal
third-party SBOM, signature, or hosted provenance attestation. The dependency-free release tool can
validate an externally generated CycloneDX 1.4 JSON SBOM when its components exactly cover the
declared direct runtime dependencies; it records the SBOM's byte count and digest alongside the
wheel and sdist. This does not prove absence of vulnerabilities, licence compliance,
reproducibility, or semantic truth. The manual attested workflow is implemented but dormant until
the exact public export/tag exists and the release owner performs the final readback and approval.

## Public quality baseline

The supported CI matrix is Python 3.11 on Linux, Python 3.12 on Linux, and Python 3.12 on Windows.
The Python 3.12 Linux entry is primary: it enforces Ruff, the explicit strict-mypy boundary, at
least 70% branch coverage, and wheel creation. The measured public-suite baseline was 74% branch
coverage on Windows/Python 3.12 on 2026-09-05; the live matrix still has to pass on the exact
release candidate. The dependency-audit job is independent and fails on known Python-package
advisories. These gates do not replace the secret scan, exact export review, security review, or
human release authority.

The package should include third-party notices if it begins redistributing dependency code or
closely ports an upstream fragment. Merely linking a package does not transfer its licence to
project-authored code, but downstream dependency licences still apply to installed distributions.

The synthetic performance check covers the initialized private-instance path and enforces the
following deterministic resource budgets at 100, 1,000, and 10,000 fictional evidence records:
`readiness()` uses at most six application `SELECT` statements and `audit_events()` at most two.
The complete local `export_user_data` path is budgeted at two application `SELECT`s per evidence
record plus a fixed 24-SELECT allowance. Export completeness requires one source and consent receipt
and exactly one revision and audit event per seeded evidence record; the receipt checksum and
serialized byte count must also agree. Source, revision, and audit-event identities are captured
from the synthetic fixture before export and must match the exported identities exactly and
uniquely. Export size is bounded at 1,500 bytes per record plus 2,048
fixed bytes. These are regression guards for this synthetic path, not repository-wide latency or
resource claims; elapsed time remains informational and is never a CI threshold.
