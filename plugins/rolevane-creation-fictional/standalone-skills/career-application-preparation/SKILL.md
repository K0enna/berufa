# Prepare requested application material

Apply the manifest gate, disclosure and writing quality pass in the
[shared writing method](../../references/writing.md) before processing supplied content.
Only `selected_text_standalone_v1` permits this workflow under the
[standalone boundary](../../references/standalone-profile.md). Obtain explicit agreement;
reuse it in this conversation until revoked or scope changes. Denial stops processing.

## Bind the task to its requested output

Use the deliberately selected posting, experience, assessment if supplied, and exact draft.
Identify what the user requests: a brief, CV, answer, letter, scoped edit or critique, with
reader, language and limits. CV-only and brief-only requests are valid. Do not add a letter,
message or application form without a request. A prior role assessment helps but no core
record, CLI or canonical decision is required for this standalone route. If fit is unsettled,
retain the unresolved gates in the brief instead of calling the application approved.

Reuse the relevant facts, prior assessment and accepted wording already shared within the
agreed scope. Ask only for a missing fact that changes this deliverable. Where a supplied
decision explicitly declines the role, do not generate an application unless the user has
reopened preparation. A supplied closed outcome is historical context, not a new invitation
to apply. Do not infer either state from a saved draft alone.

1. Identify the role's most consequential needs and map them to specific supplied experience.
   Separate direct and transferable support from gaps. Do not convert employer requirements
   into candidate qualifications or claim unsupported methods, products, credentials or scope.
2. Choose a focused positioning statement and relevant examples. Preserve exact titles,
   dates, shared attribution, approximation, units, currency and incomplete qualifications.
   Flag conflicting required facts in internal notes; omit an optional uncertain claim or
   use a clear placeholder for an essential missing field.
   Preserve strong specific results and the supplied narrative voice. Tailor the selection
   and emphasis before replacing effective wording. Do not turn the whole CV into generic
   leadership summaries or put internal gap/confidentiality notes into employer-facing prose.
3. Create a short application brief: target need, selected support, claim limits, genuine
   gaps, unknowns and the intended emphasis. Keep these editorial notes separate from the
   employer-facing text, especially confidentiality and unresolved qualifications.
4. Produce the complete requested deliverable, not only an outline. Reuse the existing
   [career drafting method](../../skills/career-create-content/SKILL.md) for complete CV
   sections, concise answers, targeted revisions and critique. Apply it directly within
   this request; do not require a second user invocation or generate unsolicited items.
5. Check each resulting claim against its selected basis, answer the actual question and
   enforce supplied length limits. Apply the shared writing pass. Keep natural voice and
   effective accepted wording; write requested languages independently.
   If the user supplies a previous document and later factual corrections, apply those
   corrections to the affected claims without declaring the entire historic package current
   or revalidated. State any remaining material source conflict in the brief.

## Deliver and stop

Return the brief and the complete requested editable material, keeping internal notes apart.
For brief-only, return only the brief. For critique-only, return findings and optional short
alternatives with no replacement or file write. A targeted edit shows old/new wording and
changes only the selected passage; preserve the rest and available newline bytes.

Requested files use new local Markdown at an explicit selected path with no overwrite and
exact readback. Unsupported file tools yield complete text with an honest no-file statement.
The retained PDF/DOCX formatter is fictional-only; do not use it for real selected content.
No sending, submission, evidence approval or application/pipeline state. Later sessions need
selected content and fresh agreement; generated material alone does not prove an application.

The [application example](../../examples/standalone-workflows.md#application) includes a
finished short answer with its bounded brief. Stop at the requested preparation artifact.
