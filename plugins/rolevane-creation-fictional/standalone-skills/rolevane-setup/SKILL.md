# Start a career brief

Read the profile gate and sharing disclosure in the
[shared writing method](../../references/writing.md) before requesting or processing content.
The exact `selected_text_standalone_v1` manifest permits this selected-text workflow under
the [standalone boundary](../../references/standalone-profile.md); no other profile grants it.
Reuse explicit agreement in this conversation until revoked or scope changes. If agreement
is denied or uncertain, stop processing content. Installation is not sharing agreement.

## Make a useful starting point

Use the goals, constraints and available experience the user deliberately pastes. Identify
what the user wants to decide or produce now. A short initial brief does not need a full CV.
When the user asks about installing Skills, explain ordinary folder installation from the
packaged README; do not require a core CLI, database, private workspace or account connection.

1. Separate present experience from desired direction. Keep aspirations out of the experience
   summary. State what successful progress would look like in the user's own terms.
2. Separate firm constraints from negotiable preferences: location, travel, work model,
   pay basis, timing and personal commitments. Do not infer minimum pay or a preference
   from an unrelated example. Mark unspecified constraints unknown.
3. Suggest plausible role directions with a supplied basis and a tradeoff for each. Use
   role families as search hypotheses, not verified vacancies or proof of qualification.
4. Choose the smallest useful next step from the user's request: organize evidence, assess
   a supplied role or draft selected material. Explain which input it needs. Do not perform
   another lifecycle stage or add an application package unless requested.
5. Ask only the few questions that could change the direction. Do useful work with available
   facts rather than turning setup into a long questionnaire.

## Deliver the brief

Return a concise brief containing the current starting point, desired direction, firm
constraints, flexible preferences, plausible role directions, unresolved decisions and a
short ordered next-step plan. Use actual supplied facts in the brief rather than a blank
template. Identify each next action and the selected material needed; do not invent deadlines
or schedule anything. Where the user gives a date, preserve it and label any suggested timing.

Keep the brief editable in chat. Requested local Markdown uses the boundary's new-path,
no-overwrite and exact-readback contract. Nothing is stored automatically. A later session
needs the selected brief and fresh sharing agreement; there is no connected profile to resume.

The [setup example](../../examples/standalone-workflows.md#setup) shows a completed brief from
a small fictional input. Stop at the requested brief or installation explanation.
